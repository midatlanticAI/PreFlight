`docs/gate3-findings-2026-09-04.md` has every one with its reproducer. Three attackers found

They collapse into four root causes, not forty separate bugs. Fix the cause, not the symptom:

**A. `probeBuildConfig` throws (G34, G35).** Highest priority: a throwing probe kills its whole
family for that scan. Line 37 dereferences `f.path` and line 91 dereferences `pkgFile.content`
with no guard. Every other v2 family already guards with `(f.content || '')`. Two guards, done.
The probe contract is: always return an array, never throw, whatever the input.

**B. String-blind span scanners (G36, G39, and the react/errors span findings).** `readCallSpan`,
`cleanupIsOpaque`, `readBraceSpan` and the `paramUses` count all read raw source, so a `)` or `}`
or the catch parameter's name _inside a string literal_ truncates a span or vouches for handling
that is not there. A correct effect gets accused because someone wrote `console.log('done :)')`.
The blanking helper already exists in the same files (`spanShape`, `bodyShape`) and is applied
too late. Blank strings **before** scanning, once, and feed the scanners the blanked view while
keeping raw text for evidence.

**C. Structural regex holes (G37, G38, G40, and the rest of the logic set).** Each is a pattern
that cannot match a mainstream spelling: `catch (e: unknown)` in the .ts files the family
explicitly claims; loop headers containing a call, so `for (const id of Object.keys(map))` is
invisible; a dead `(^|/)` alternative mid-pattern that excludes root `app/page.tsx`; `depsOf`
matching the _first_ `}` instead of the last; `$` in an identifier interpolated into a dynamic
`RegExp` becoming an anchor. Fix each where it is, and pin the spelling that was missed.

**D. Superlinear scans, 10 findings, one shared cause.** Nine of the ten are the same mistake:
O(n) work recomputed per match. `lineOf(code, idx)` re-slices and re-splits the whole file prefix
for every effect, catch, loop and route (react, errors, async, api-patterns, data-state);
`usesKnex` and `/:focus-visible/` re-scan the entire file inside a per-line loop (db-patterns,
a11y). At 400KB these run 0.8s to 7.3s; the budget is well under 1s. The fix is one small shared
helper in `src/lib/probes/v2/` that builds a line-offset array once per file and answers
`lineAt(offset)` by binary search, plus hoisting the two loop-invariant regexes out of their
loops. That is one helper and a handful of call-site edits, not a refactor. The remaining item
(G33, the `.map` key regex backtracking on minified lines) needs the regex bounded, not the
helper.

Add pins for every fix in a new `src/test/v2-families-gate3-2026-09.test.js`, matching the shape
of the two existing pin suites.

## How this codebase is written

The founding principle is in `CLAUDE.md` and it is not decoration: PreFlight scans its own
`dist/` in CI and must come back clean. It ships an "AI Codegen Bloat" probe. Code that would
embarrass the tool fails the tool. That constrains style more than any lint rule.

### Do not bloat it

This is the rule John cares about most, so it comes first.

- **Write the smallest thing that is correct.** A probe check is usually a regex, a guard, and a
  push. If a check is growing past roughly 30 lines, the detection idea is probably wrong, not
  the implementation.
- **No speculative abstraction.** No base class, no options object, no registry, no "engine" for
  one caller. The families are pure functions over `files: {path, content}[]` and share exactly
  four `_internal` helpers because those had three or more real callers each. Two call sites is
  not a helper; it is two call sites.
- **No new dependencies.** The stack is React, Vite, Vitest, acorn, react-markdown. Adding a
  package to save fifteen lines is a bad trade in a tool whose entire pitch is that it runs in the
  browser with no backend.
- **No defensive scaffolding.** Inputs are known-shaped. Guard `content` and `path` because the
  contract says never throw, and stop there. No try/catch around code that cannot throw, no
  null-checks on values you just constructed, no logging "for debugging".
- **Delete the roster entry instead of building a weak check.** Every family header lists the
  planned checks that were _not_ built, with the reason (FP-dominated, needs dataflow the engine
  does not have, already owned by another probe). That list is a feature. A check that fires on
  arguable code is worse than no check, because it teaches the user to ignore the tool.
- **One discipline, one module.** When the same judgment appears in three files it drifts, and the
  drift is where the false positives live. `credential-shape.js` exists because "is this name a
  credential" was implemented three different ways. Consolidate on the third occurrence, not the
  first.
- **Comments carry constraints, not narration.** Say why a regex is bounded, why a case is
  exempt, what adversarial finding forced this guard, what breaks if you change it. Never restate
  what the next line does. The existing headers and inline notes are the register to match:
  concrete, sourced to a reproduced case, no hedging.
- **Match the file you are editing.** Its naming, its comment density, its idiom. A file should
  not read like two authors.

### Probe contract, non-negotiable

- Pure function, `(files) => Finding[]`. Always an array. Never throws, on any input: content
  null, undefined, empty, binary, unterminated strings, 400KB single-line minified bundles, paths
  with regex metacharacters. `detect([])` returns `[]`.
- Under one second on a 400KB file. No O(n) work per match; no whole-file regex inside a per-line
  loop; bound your quantifiers.
- Finding shape: `{id, probe, title, severity, category, cwe, file, line, evidence, remediation}`.
  `finding.probe` must byte-match the registry name. `line` is 1-based. `evidence` is
  `line.trim().slice(0, 200)` and must never echo a secret.
- Probes never match code patterns in comments or prose. Pick the mask view deliberately:
  `maskCommentsForPath` for comment-blind, `maskCodeShapeForPath` when string contents would
  confuse the check. The secrets family is the deliberate exception: a committed secret is leaked
  whether or not it sits in a comment.
- Every suppression must trace to a reproduced false positive, and the case goes in the comment.
  Never suppress a finding to make a number look better, and never suppress one of PreFlight's
  findings against PreFlight itself. Fix it for real.

### Verifying your own work without burning a fortune

This session spent 18.85M tokens across 276 subagents, and 13.36M of that went to 236
verification agents that each re-derived context to answer one deterministic question. Do not
repeat that.

- If the question is "does this fixture produce this finding", it is a script. Write a `.mjs` in a
  scratch directory that imports `PROBES` from `src/lib/probes.js`, run it, read the output. Two
  tool calls, no agent.
- Adversarial review by a fresh reader is genuinely valuable and worth keeping, but batch it: one
  reviewer for a whole family of claims, not one per claim.
- Never run two heavy fan-outs at once, and never resume one that already died on a limit without
  checking what is left first.

### Environment notes that will bite you

- Windows, Git Bash plus PowerShell. Inline `node -e` **fails silently** here. Always write a
  script file.
- A python heredoc turns `\b` in a string into a literal backspace byte (0x08). It has silently
  corrupted a regex in this repo twice. If a pattern mysteriously never matches, run `cat -A` on
  the line.
- Prettier reformats after `npm run format`, which invalidates edit anchors. Re-read before
  editing.
- Files are CRLF. Multi-line exact-match edits often fail on that alone; prefer single-line
  anchors.
