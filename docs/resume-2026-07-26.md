### The two that matter most

**The masker was blinding the scanner.** `maskCommentsAndStringsFromContent`
did not understand regex literals, so the `"` inside
`String(s).replace(/[&<>"']/g, …)` opened a string that ran to the next
unrelated quote. On one real file that blanked lines 442 through 1098. Every
masked-content check in that range simply did not run. `escapeHtml` written
exactly that way is in a large share of generated apps, so this was truncating
analysis across a large fraction of all scans. Silent, and in the worst
direction: fewer findings reads as cleaner code.

**Directory rules were lost to backslashes.** Every rule in `file-filter.js` is
written with `/`. A caller using `path.join` on Windows supplies `\`, and then
`isTestFile`, `isScannerSelfSource` and every vendor and fixture exclusion
returned false while `shouldScanFile` still returned true. The file got scanned
with all protection off and nothing said so. Visible symptom: a project with a
real SSRF test suite scores worse than one with no tests, because the fixtures
proving `169.254.169.254` is blocked read as production code reaching for it.
Normalised at the single door every rule passes through.

**B. #5 `fetch` with no `r.ok` check.** `await fetch(url).then(r => r.json())`

`scanBackToExpressionStart` and `expressionHasOwnCatch` rather than writing a
third chain walker.

**C. The two small AST matches, #9 and #10.** `import _ from 'lodash'` (69KB for
one helper) and `@ts-ignore` / `@ts-expect-error` with no explanation on the
same or previous line. Both near-zero FP risk, both single matches. Good filler
work when context is short.

**D. #2 broad catch, last of the easy ones.** Existing empty-catch check lives
in `llm.js:322`. Extend to "catch parameter referenced only inside a
`console.*`". Watch the boundary: a catch that logs _and_ re-renders an error
state is handled, not swallowed.

**E. #3 unknown npm import — leave for last, it has a real design question.**
Needs a bundled registry name snapshot, which is a size-versus-freshness
tradeoff nobody has decided. Do not start this without deciding: how big a

a private/scoped package. Spracklen et al. USENIX 2025 is the anchor (19.7% of

## Two decisions waiting on you

**The health-score ceiling.** Scoring is per class with a sublinear repeat
multiplier, so six distinct classes of health finding cost 16 points _at one
instance each_. That caps a project around 84 no matter how much it cleans up.
Nobody chose that number. It is the thing that will cap users who actually do
the work. Worth deciding before pushing further on health.

**Atlan's Term tab.** `index.js:469` passes `cwd` straight from the WebSocket
into `openPty` with no `guardPath`, while `/api/file` refuses credential paths.
Verified still open. Do **not** "fix" it by adding `guardPath` to `cwd` — a
shell can `cd`, so that changes nothing while looking like a fix. The real
question is whether the agent should be able to drive `pty.open` at all, or
whether it is human-only. That is an architecture call, not a patch.

## Rules this session earned, in addition to yesterday's

- **Fetch before you reason.** Three times today I analysed a stale checkout,
  twice after being told. `git fetch` costs seconds. Lead with it.
- **A suspicious improvement is a bug report.** The `.then` fix took findings
  from 40 to 0 with every test green. Zero was the tell. The suite could not
  catch it because the suite was testing the thing that broke. Consider a gate:
  a probe change that drops a previously-confirmed corpus to zero should fail.
- **A confident comment is not evidence.** Two bugs today sat under
  well-written justifications: the catch-clause guard ("precision-favouring by
  decision, not oversight") and the `.npmrc` comment asserting npm implements
  `min-release-age`. Neither had been checked. A comment that argues for a
  choice should be a flag for review, not a reason to skip it.
- **Verify config keys against the tool.** `npm config ls -l` echoes unknown
  `.npmrc` keys back, which is exactly why an inert setting looked accepted for
  months. Same class as the threat-intel version strings.
- **Fixtures cut both ways.** Yesterday's lesson was fixtures lie (they pass
  while real code breaks). Today's is the mirror: fixtures read as production
  risk, so writing a real SSRF test suite lowers your score, and a fixture's
  bait import installed a real package into a downstream cockpit.
