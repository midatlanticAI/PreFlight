## What started it

A GitHub-URL scan of this repo returned **0 / 100, 236 findings, 14 critical**.
Every critical was a comment or a string in our own probe source.

The fix mattered far beyond the false positives.

**The narrow masker never learned to lex.** It honoured backticks without
tracking `'` or `"` at all, so one backtick inside an ordinary quoted string
opened a template literal that ran to the next backtick anywhere later in the
file. Two consequences, and the second never appeared in any report:

1. Comment text caught between the phantom pair was emitted as code.
2. Every real line the phantom swallowed was blanked, so no masked check ran on
   it. **353 of 1,371 lines in `auth.js`. 110 of 367 in `llm.js`.**

Backticks in comments are ordinary in documented code. This was not about us.

---

## The rules this session earned

- **A masking bug is bidirectional, and the invisible half is the dangerous
  one.** Leaked comments produce noise somebody can see. Swallowed code produces
  a clean report. Always measure both directions.
- **An unterminated construct is evidence of a mis-lex, not of a giant
  comment.** `src/data/*` in JSX copy opened a block comment nothing closed and
  blanked 95 of 187 lines of our own `TermsView.jsx`. Prefer under-masking.
- **Do not test one probe in isolation and report it as the product.** The
  claim "the SSRF probe misses everything" was wrong and shipped in a commit
  message before being corrected; the taint engine catches all of it. Run the
  probe set the app runs.
- **Grammar beats vocabulary.** "Does this contain a code keyword" fires on
  English constantly. Function-word ratio separates prose from source; `if`,
  `for`, `return` and `class` do not.
- **A guard that suppresses findings is a security control.** The prose guard
  asked whether a line _contained_ prose while callers used it to skip the whole
  line, so one readable sibling property silenced criticals. Shipped and fixed
  the same day.
- **Score the corpus, not the repo.** Reserved IPs were nearly dropped from URL
  Reputation on the assumption SSRF covered them. It did not. That would have
  bought 100/100 by deleting a check. Reverted within the hour; 95 is honest.

## Queue, in order

1. **Multi-line SQL.** A `db.query(` whose template literal opens on the _next_
   line misses. The callee regex needs the backtick on the same line, and the
   four-line `span` only widens the interpolation check, never the callee match.
   Prettier produces this shape constantly, so it is likely the most common real
   SQL-injection miss.
2. **No weak-crypto probe.** ECB, DES/3DES and static IV have no coverage at
   all, and JS md5/sha1 only fires when the variable is literally named
   `password` — the construct is not what triggers it.
3. **No server-side reflected XSS.** `res.send("<h1>" + req.query.name)` is
   silent.
4. **JS TLS verification disabled.** `rejectUnauthorized: false` and
   `NODE_TLS_REJECT_UNAUTHORIZED=0` uncovered; the Python analog is covered.
5. **Two-step builds generally.** `const sql = …; db.query(sql)` and
   `const cmd = …; exec(cmd)` both miss. The taint engine is the right home.
6. Smaller, verified: `jwt.decode` used as auth; `jwt.verify(token, undefined)`;
   reversed-operand password comparison; hoisted `__html` object;
   `.vue` `v-html`; the 40-char half of an AWS key pair.

## The 1000-repo mission (John, 2026-07-27)

Scan ~1,000 open GitHub repos in batches to settle recall and FP rate on code
nobody here chose, and collect teaching sources for Learn along the way.

**The piece to design first is adjudication, not scanning.** A sweep produces
findings; only judgement decides which were wrong, and without that step it
produces a big number and no knowledge. Intended shape: sample by language and
stars → scan → cluster findings by probe + shape → surface one exemplar per
cluster for a human call → feed verdicts back as fixtures. That turns 1,000
repos into dozens of decisions rather than thousands.
